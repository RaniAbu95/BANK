# Deployment (free tier)

| Part | Where | Notes |
|---|---|---|
| MySQL | [Aiven](https://aiven.io) free MySQL plan | Requires SSL |
| Server (Spring Boot) | [Render](https://render.com) free web service, built from `Dockerfile` | Sleeps after ~15 min idle; first request after that takes ~1 min |
| Client (React) | [Cloudflare Pages](https://pages.cloudflare.com) | Static site from `client/` |

## 1. Database — Aiven

1. Create a free MySQL service.
2. From the service overview, copy host, port, user and password.
3. The JDBC URL for the server is:

   ```
   jdbc:mysql://<host>:<port>/Bank?sslMode=REQUIRED&createDatabaseIfNotExist=true
   ```

Tables are created by Hibernate on first start (`ddl-auto=update`).

## 2. Server — Render

1. Push this branch to GitHub.
2. In Render: **New → Blueprint**, pick the repo. Render reads `render.yaml` and creates the `bank-server` service.
3. Fill in the environment variables it asks for:

   | Variable | Value |
   |---|---|
   | `DB_URL` | JDBC URL from step 1 |
   | `DB_USERNAME` / `DB_PASSWORD` | Aiven credentials |
   | `ADMIN_PASSWORD` | Password for the `ADMIN` user created on startup |
   | `RESEND_API_KEY` | API key from [Resend](https://resend.com) for verification emails (Render's free tier blocks SMTP, so Gmail doesn't work there) |
   | `RESEND_FROM` | Sender, e.g. `Bank <bank@rani-support.com>` on a domain verified in Resend. Leave empty to use `onboarding@resend.dev`, which only delivers to your own Resend account address |
   | `CORS_ALLOWED_ORIGINS` | The Pages URL from step 3, e.g. `https://bank-client.pages.dev` (comma separated for several) |
   | `GOOGLE_CLIENT_ID` | OAuth client ID for "Continue with Google" (see [Google sign-in](#google-sign-in)). Leave empty to turn it off |

   `JWT_SECRET` is generated by Render. `PORT` is set by Render automatically.
4. After the deploy, note the service URL, e.g. `https://bank-server.onrender.com`.
5. Make sure the **Render** GitHub App is installed on the repo (GitHub → Settings → Applications → Installed GitHub Apps). Without it Render can still build a public repo on a manual deploy, but pushes to `main` don't trigger an auto-deploy.

## 3. Client — Cloudflare Pages

1. **Workers & Pages → Create → Pages → Connect to Git**, pick the repo.
2. Build settings:

   | Setting | Value |
   |---|---|
   | Root directory | `client` |
   | Build command | `npm run build` |
   | Build output directory | `dist` |
   | Environment variable `VITE_API_URL` | Server URL from step 2 (no trailing slash) |
   | Environment variable `VITE_GOOGLE_CLIENT_ID` | Same value as `GOOGLE_CLIENT_ID` on Render. Without it the Google button is hidden |

3. Deploy, then put the Pages URL into `CORS_ALLOWED_ORIGINS` on Render if you haven't yet (Render redeploys on env change).

`client/public/_redirects` sends every path to `index.html` so client-side routes like `/admin` work on refresh.

### Serving the client under a path (e.g. `rani-support.com/bank`)

1. In Pages, add the build variable `BASE_PATH=/bank/` and redeploy. Asset URLs and client routes then live under `/bank/`.
2. In the site that owns the domain (Vercel), add rewrites to `vercel.json`:

   ```json
   {
     "rewrites": [
       { "source": "/bank", "destination": "https://<project>.pages.dev/" },
       { "source": "/bank/:path*", "destination": "https://<project>.pages.dev/:path*" }
     ]
   }
   ```
3. Set `CORS_ALLOWED_ORIGINS` on Render to that site's origin, e.g. `https://rani-support.com`.

With `BASE_PATH` set, the `*.pages.dev` URL itself no longer works directly — only through the rewrite.

## 4. Keep the server awake — UptimeRobot

Render's free instance sleeps after ~15 min without traffic. A free monitor that calls `/health` every 5 min keeps it awake (one always-on service fits in Render's 750 free hours a month).

1. Sign up at [uptimerobot.com](https://uptimerobot.com).
2. **New monitor**: type **HTTP(s)**, URL `https://<your-service>.onrender.com/health`, interval **5 minutes**.

If the server does fall asleep, the client wakes it on page load and shows a "server is waking up" banner while requests take longer than 3 seconds.

## Google sign-in

The login and signup pages show a "Continue with Google" button. The first Google login creates a user (name taken from the email), a customer and a bank account, already email-verified. Later logins go to the user with that email. If a password user with that email exists but never verified it, Google login is refused, so whoever registered that email can't share the account.

1. In [Google Cloud Console](https://console.cloud.google.com/apis/credentials): **Create credentials → OAuth client ID**, type **Web application** (set up the OAuth consent screen first if asked).
2. Under **Authorized JavaScript origins** add every origin the client runs on, without a path: `http://localhost:5173`, `http://localhost`, and the production origin (e.g. `https://rani-support.com` or `https://<project>.pages.dev`). No redirect URIs are needed.
3. Put the client ID in `GOOGLE_CLIENT_ID` on Render and `VITE_GOOGLE_CLIENT_ID` on Pages, then redeploy both.

For a local run: `export GOOGLE_CLIENT_ID=...` before starting the server, and `VITE_GOOGLE_CLIENT_ID=...` in `client/.env.local` (or the shell) before `npm run dev`.

## Local run

Nothing changes: every new setting has a default matching the old values, and in dev the Vite proxy avoids CORS.

To try the server image locally:

```bash
docker build -t bank-server .
docker run -p 8081:8081 -e DB_URL=jdbc:mysql://host.docker.internal:3306/Bank bank-server
```
